# Output marking

A factual record of how this project marks generated speech and why, for the
operator to review. **No claim of legal compliance is made.** Whether and how
Article 50 of the EU AI Act applies to a deployment, and whether the measures
below are sufficient, is the operator's assessment.

## The requirement text

Regulation (EU) 2024/1689, Article 50(2):

> Providers of AI systems, including general-purpose AI systems, generating
> synthetic audio, image, video or text content, shall ensure that the outputs of
> the AI system are marked in a machine-readable format and detectable as
> artificially generated or manipulated. Providers shall ensure their technical
> solutions are effective, interoperable, robust and reliable as far as this is
> technically feasible, taking into account the specificities and limitations of
> various types of content, the costs of implementation and the generally
> acknowledged state of the art, as may be reflected in relevant technical
> standards. This obligation shall not apply to the extent the AI systems perform
> an assistive function for standard editing or do not substantially alter the
> input data provided by the deployer or the semantics thereof, or where
> authorised by law to detect, prevent, investigate or prosecute criminal
> offences.

The Commission's guidelines C(2026) 7702 (5 November 2026) treat marking and
detection as two elements and weigh effectiveness, robustness and cost together;
see the release review for the source list.

## What we do (default: metadata)

Owner decision (2026-11-25): metadata marking, clearly stated; the audio
watermark is not on by default.

- **Every WAV file the page exports** (the download link and `window.tts.wav(id)`)
  and every WAV file the Python package writes (`Release.synthesize_wav`,
  `designed_tts.mark.export_wav`) carries two standard metadata chunks after the
  data chunk: RIFF `LIST`/`INFO` with `ISFT` = `Designed Voices TTS` and
  `ICMT` = `AI-generated speech (<model> <voice>), generated by Designed Voices
  TTS. Check: python -m designed_tts.mark detect`, and an XMP packet (`_PMX`) with
  the IPTC digital source type
  `http://cv.iptc.org/newscodes/digitalsourcetype/trainedAlgorithmicMedia` and
  `xmp:CreatorTool`. They hold the generator, model and voice ids, never the
  entered text, a time or anything about the user. The 44-byte header stays the
  canonical one; `ffprobe`, `ffmpeg`, `afinfo` and Python's `wave` read the files.
- **The audio is the model output.** With the default the page downloads no
  marker file; playback, waveform and PCM equal the unmarked outputs (identity
  hashes of the configuration C record).
- **The page says so**, in the model and runtime paragraph, in both languages:
  "Heruntergeladene WAV-Dateien enthalten Metadaten, die sie als KI-erzeugte
  Sprache kennzeichnen." / "Downloaded WAV files contain metadata that marks them
  as AI-generated speech." The Space card, the README and the model cards say the
  same, with how to read it.
- **Detector:** `just detect FILE...` or `python -m designed_tts.mark detect
  FILE... [--marker DIR]` prints one JSON line per file: `metadata`
  (`ai_generated`, `generator`, `comment`, `digital_source_type`, or `null` when
  the file has none) and `watermark` (`null`, or with a watermark model the score,
  decision and matching message bits). On the page, `await
  window.tts.detect(arrayBuffer)` returns `{metadata, watermark}` in the same
  sense; `watermark` is `null` unless the build has the watermark model. Any tag
  reader shows the metadata too: `ffprobe -show_format FILE` lists it as `comment`
  and `encoder`.

Limits: metadata is removed by any conversion (MP3, resampling, re-recording) and
can be stripped on purpose. It marks files, not audio played elsewhere.

## Why the audio watermark is not on by default

An AudioSeal watermark (MIT code and weights) was built, measured and offered to
the owner (sections below). It is not the default because:

- **It is audible.** Owner blind test, marked against unmarked, same sentence and
  voice (9 of 16 pairs rated): unmarked preferred 6, marked 0, tie 2, both bad 1.
  The owner hears a faint higher-frequency sound on the marked versions.
- **It costs:** +58.8 MB download with the first synthesis; first output on this
  Mac 1.86 s to 3.33 s (German Kale); synthesis real-time factor about three times
  higher (0.056 to 0.164).
- **Any open-source deployer can switch it off**; it is one setting in code that
  is published.

Kyutai states the same reasons for its TTS 1.6B model
(https://huggingface.co/kyutai/tts-1.6b-en_fr, card at revision
`f65439609986c392cb12df63938abcc550c3fb15`, quoted verbatim):

> This model does not perform watermarking for two reasons:
> - watermarking can easily be deactivated for open source models,
> - our early experiments show that all watermark systems used by existing TTS
>   are removed by simply encodeding [sic] and decoding the audio with Mimi.

Our own measurements did not include neural-codec re-encoding; the watermark
survived MP3 at 64 kbit/s, resampling, gain, noise and cuts (table below).

## The watermark option

Marking modes (build: `marking` in the preview config; Python: `load_release(...,
marking=...)`):

| Mode | Samples | WAV metadata | Marker files served |
| --- | --- | --- | --- |
| `metadata` (default) | model output | yes | none |
| `watermark` | model output plus AudioSeal watermark | yes, and the comment names the watermark | `mark.onnx`, `detect.onnx` |
| `off` | model output | no | none |

`off` (or `false`) is for people who deploy the app themselves.
`tools/upload-space.py` accepts a package marked with `metadata` or `watermark` and
refuses `off`. The packager writes the Space card's marking section to match the
mode. Visitors of a build cannot change the mode.

With `watermark`, the worker adds the watermark to every segment before anything
is listed, drawn, played or exported; a marker that fails to load or apply stops
the synthesis with a plain error, never with unmarked output. `result.audio`
stays the model output for the parity gates. Python: `marking="watermark"` with
`marker=<directory>` or `DESIGNED_TTS_MARKER`; loading fails without one.
Qualified build options for this mode: `marker_variant = "float16"` (half-float
marker, 29.5 MB) and `marking_worker = true` (the generator in a second worker).

### Choice and integration

AudioSeal 16-bit (Meta): code MIT (`facebookresearch/audioseal` `1496f766`,
`audioseal` 0.2.1), weights MIT (`facebook/audioseal` `3c19eba5`, card `license:
mit`). Not chosen: WavMark (MIT; 1-second segments, detection by a shift search),
Perth (MIT; 32 kHz STFT resynthesis, no localized score); rejected: SilentCipher
(weights licence unclear), Timbre watermarking and audiowmark (GPL-3.0); SynthID
is not open. `tools/export-marker.py` exports the generator and detector as
CPU-WASM ONNX graphs from the pinned, hash-checked checkpoints (loaded with
`weights_only=True`), byte-reproducibly, within 6e-6 of the eager models.

The models produce 24 kHz audio, AudioSeal works at 16 kHz: only a copy of the
speech is resampled to 16 kHz to compute the watermark; the watermark is
resampled to 24 kHz and added to the unchanged samples (inside `mark.onnx`), so
the speech above 8 kHz is untouched. The detector runs at four offsets a quarter
of its 320-sample hop apart and keeps the best; a file is reported as watermarked
when at least half of its samples score above 0.5.

### Measurements (2026-11-25, silent)

152 held-out outputs of configuration C from the page (all 72 voices, rates 0.8
and 1.3); false positives on the unmarked outputs and on the first 200 clips of
FLEURS de_de test (`fleurs-de-test-asr-eval/v1`, CC BY 4.0, Conneau et al. 2022).

| Transformation | Detected, marked outputs | False positives, unmarked outputs | False positives, human speech |
| --- | --- | --- | --- |
| none | 152/152 | 0/152 | 0/200 |
| MP3 128 kbit/s | 152/152 | 0/152 | 0/200 |
| MP3 64 kbit/s | 152/152 | 0/152 | 0/200 |
| resampled to 16 kHz | 152/152 | 0/152 | 0/200 |
| resampled to 44.1 kHz | 152/152 | 0/152 | 0/200 |
| gain -6 dB | 152/152 | 0/152 | 0/200 |
| gain +6 dB, clipped | 152/152 | 0/152 | 0/200 |
| white noise at 30 dB SNR | 150/152 | 0/152 | 0/200 |
| 0.5 s cut from both ends | 135/135 | 0/135 | 0/200 |
| cut at a random start sample | 151/151 | 0/151 | 0/200 |
| 1-second excerpt | 133/135 | 0/135 | 0/200 |

Lowest marked score untransformed 0.93, highest unmarked 0.18, highest human 0.35.
Not tested: removal attacks, speed or pitch changes, neural codecs, loudspeaker
playback. Watermark-to-speech SNR 22.0 to 36.4 dB (median 28.2); log-mel L1 median
0.140. These objective measures did not predict the owner's result above.

Cost, this Mac only (Chrome headless, CPU WASM, one thread, loopback, medians of
three cold runs; first output = German Kale sentence of 3.65 s, real-time factor =
11 s English text):

| Variant | Download (mark / detect) | First output | Marking per audio second | Real-time factor |
| --- | --- | --- | --- | --- |
| no watermark | - | 1.86 to 1.88 s | - | 0.057 |
| float32 marker | 58.8 / 34.7 MB | 3.33 to 3.46 s | 108 ms | 0.163 |
| float16 marker | 29.5 / 17.4 MB | 2.88 s | 109 ms | 0.165 |
| marker worker | 58.8 / 34.7 MB | 2.60 s | 116 ms | 0.137 |
| float16 + marker worker | 29.5 / 17.4 MB | 2.34 s | 107 ms | 0.127 |

The float16 marker and the marker worker passed the same gate as float32 (same
detection and false-alarm counts, SNR range, unmarked identity); int8 weights and
a polyphase rewrite also passed but gave no further gain and are not wired.
Variant work was stopped on 2026-11-25 after the listening result. Receipts:
`tts-browser-runtime/v5` and `v6`, `qualification/MARKER-*`.

## Gates

- `tools/check-marking.mjs` (in `just check-preview`) checks the build's mode.
  Metadata: no marker file is requested; every family, a slower and a faster rate
  and a comparison voice give the unchanged model output; the download and
  `window.tts.wav` carry the metadata and nothing about a watermark; `detect()`
  reports the metadata and no watermark; the page sentence is shown in both
  languages; no watermark row in the timing table; no new control. Watermark and
  off: the corresponding checks.
- `tools/check-runtime-identity.mjs` compares the unmarked model output with a
  reference (`REFERENCE=`) and records watermarked hashes as a separate stage.
- `tests/test_mark.py`, `tests/wav.test.mjs`: browser and Python WAV bytes and
  metadata are equal (`tests/fixtures/wav-metadata.json`), the readers, the modes.
